# Deep Diff Engine

[English](DeepDiff.md)

`vardiff::deep_diff(before, after, options, keys...)` сравнивает два const-объекта
без наблюдателя и снимков. Сохраняются C++20, один заголовок и отсутствие
зависимостей. Используются те же схемы, компараторы полей, рекурсивный обход
и владеющий значением `value`, что и в `diff()` и `watcher`.

## Пример

```cpp
#include <vardiff/vardiff.hpp>

struct Item { int id; int count; };
template <> struct vardiff::schema<Item> {
    static auto fields() {
        return std::make_tuple(vardiff::field("id", &Item::id),
                               vardiff::field("count", &Item::count));
    }
};

const std::vector<Item> before{{1, 10}, {2, 20}, {3, 30}};
const std::vector<Item> after{{2, 20}, {3, 30}, {1, 12}};
const auto changes = vardiff::deep_diff(before, after, vardiff::key(&Item::id));
// moved: from="[0]", name="[2]", old_index=0, new_index=2
// modified: name="[2].count", before=10, after=12
const auto stats = vardiff::summarize(changes);
// stats.moved == 1, stats.modified == 1, stats.total == 2
```

[Полный пример](../examples/deep_diff.cpp) содержит инвентарь с vector и
`map<string, optional<Item>>`. Для зарегистрированного корневого объекта
получаются пути вида `inventory[2].count`. Можно сравнивать также корневые
контейнеры и скалярные значения; путь изменения корневого скаляра — пустая строка.

## Результат и пути

Результат — `std::vector<vardiff::deep_change>`. `deep_change` расширяет
существующий `change`, сохраняя его прежний агрегат из четырёх полей.

| Поле | Значение |
| --- | --- |
| `name` | Полный путь в новом состоянии; для удаления — в исходном |
| `kind` | `modified`, `added`, `removed` или `moved` |
| `before`, `after` | Собственные копии значений; отсутствующая сторона пуста |
| `from` | Полный исходный путь перемещения; для остальных событий пуст |
| `old_index`, `new_index` | Исходный и конечный индексы перемещения; иначе пусты |

У перемещения `before` и `after` пусты: перемещённый объект не копируется.
Изменённые поля перемещённого объекта порождают дополнительные события по новым
путям. Добавление/удаление выдаёт одно событие со всем элементом, без раскрытия
листьев. При смене наличия optional сохраняется его содержимое, как в прежнем API.
Добавленный слот vector с пустым optional имеет непустой `value`, содержащий
пустой `optional<T>`.

Поля разделяются точкой, индексы начинаются с нуля, словари используют ключи:
`groups[4][0].count`, `equipment["hand"].count`. Строковые ключи заключаются
в кавычки; кавычки, обратная косая черта и управляющие байты экранируются:
`\"`, `\\`, `\u000a`. Целые ключи и enum выводятся десятичными числами.
Остальные ключи требуют однозначного `operator<<`; результат с классической
локалью заключается в кавычки. Для вещественных ключей используется
`max_digits10`. Имена полей схемы по-прежнему должны быть непустыми и не содержать
точек и квадратных скобок. Для ключей-указателей с собственной идентичностью
используйте тип-обёртку с однозначным выводом.

События описывают два исходных состояния, а **не исполняемый patch**. Все индексы
относятся к целым исходным контейнерам, а не к промежуточным шагам применения
изменений. Элемент может входить в минимальный набор перемещений, даже если
его исходный и конечный числовые индексы совпадают: учитывается порядок среди
сохранившихся элементов.

[`summarize()`](API.ru.md#статистика-изменений) подсчитывает добавления, удаления,
модификации и перемещения без копирования значений и повторного сравнения.

## Ключи и перемещения

```cpp
vardiff::deep_options options;
options.detect_moves = true; // Значение по умолчанию.
options.duplicates = vardiff::duplicate_key_policy::reject;
auto changes = vardiff::deep_diff(before, after, options, vardiff::key(&Item::id));
```

`key(&Item::id)` действует на все встреченные vector/array с элементами,
допускающими этот указатель на член, включая производные типы. Для ключа нужно стабильное отношение эквивалентности
через `==`; собственный `std::hash` должен согласовываться с ним. Член может не входить в `schema<Item>`: идентичность и сравниваемые поля
независимы. Ключи заимствуются непосредственно из элементов, без копирования;
разрешены типы с удалённым move-конструктором. Нулевой указатель на член
вызывает `std::invalid_argument`.

`key("inventory", &Item::id)` ограничивает правило указанным точным путём
контейнера. Правило пути приоритетнее правила типа. При нескольких правилах
одинаковой специфичности используется первое. Аргумент options можно опустить
перед ключами. Без ключей используйте `deep_diff(a, b)` или
`deep_diff(a, b, options)`.

По умолчанию первая запись с ключом в before сопоставляется с первой в after,
вторая со второй и так далее. Этот стабильный FIFO-порядок задаётся политикой
`duplicate_key_policy::match_in_order`; лишние дубликаты добавляются/удаляются.
Политика `reject` проверяет оба контейнера даже при отсутствии изменений
и вызывает `std::invalid_argument` при дубликатах. Исключённые контейнеры
не обходятся и не проверяются. При коллизиях хеша используется равенство ключей.

Без явного ключа сопоставляются полные значения элементов по регистрации/равенству
в FIFO-порядке. Оставшиеся несопоставленными элементы на одинаковой позиции
сравниваются как изменения; остальные добавляются/удаляются. Идентичность
одновременно изменённого и переставленного объекта без ключа неоднозначна:
задайте ключ, если предметная область определяет эту идентичность.

Наибольшая возрастающая подпоследовательность исходных индексов остаётся
стабильной, остальные совпадения считаются перемещениями. Их число минимально
для выбранного сопоставления. Вставка/удаление не создаёт перемещений всех
соседних элементов. `detect_moves=false` отключает события перемещения,
сохраняя сопоставление по ключам; без ключей возвращается сравнение по индексам.

## Словари и восстановление

`std::map` и `std::unordered_map` сопоставляются через их собственные
сравнение/хеш/равенство ключей, значения обходятся рекурсивно. Rehash не является
изменением. `key()` применяется только к последовательностям. При эквивалентных
ключах с разным представлением путь совпавшей записи использует новый ключ.

Словари также поддерживаются существующими `field()`, `diff()`, `changed()`,
`track()`, callbacks и историей. Восстановление рекурсивно обновляет существующие
значения, удаляет лишние ключи и копирует недостающие записи. Незарегистрированные
поля и исключённые пути сохраняются в существующих записях. Целиком исключённая
запись словаря не удаляется и не создаётся. Новая запись берётся из снимка целиком.

Порядок обхода определяется регистрацией. В последовательностях сначала идут
удаления по старым индексам, затем добавления/совпадения по новым; перемещение
предшествует изменениям полей своего элемента. В словарях сначала обходятся старые
записи (удаления/совпадения), затем добавленные новые. У `unordered_map` порядок
событий зависит от порядка итерации; для независимого от него сравнения используйте
путь и вид события.

## Параметры, ограничения и исключения

| Параметр | По умолчанию | Контракт |
| --- | --- | --- |
| `detect_moves` | `true` | Определять перестановки последовательностей |
| `duplicates` | `match_in_order` | Сопоставлять дубликаты FIFO или отклонять явные повторяющиеся ключи |
| `max_depth` | `256` | Максимальная посещённая глубина; корень имеет глубину ноль |
| `ignored_paths` | пусто | Исключить путь и потомков с прежними границами префикса |

Глубина увеличивается для поля структуры, элемента последовательности, значения
словаря и содержимого optional. Превышение вызывает `std::length_error`.
Лимит защищает рекурсивное сравнение, включая проверку равенства при сопоставлении.
Целиком добавляемые/удаляемые значения, пользовательские компараторы и копирование
атомарны: их внутреннюю рекурсию контролируют соответствующие типы.
Пустой исключаемый путь вызывает `std::invalid_argument`.
Исключения применяются к новым путям совпадений/перемещений и старым путям
удалений. Они фильтруют события, сохраняя сопоставление и минимальный набор
перемещений.

Пользовательский компаратор поля сохраняет атомарность: всё поле выдаёт одно
изменение, без внутреннего сопоставления и перемещений. Компараторы должны
быть чистыми, стабильными и вызываться как const. Объекты должны жить и оставаться
неизменными на время вызова. Callbacks не вызываются. Ошибки сравнения, копирования,
хеширования, равенства ключей и выделения памяти передаются вызывающему коду,
исходные объекты не меняются. Циклы через указатели не обходятся. Значения
результата копируются с обычной семантикой соответствующих пользовательских типов.

## Стоимость и совместимость

Для хешируемых ключей ожидаемая стоимость сопоставления — O(n+m), выбора
перемещений — O(k log k), где k — число совпадений. Плохие хеши ухудшают поиск.
Ключи только с равенством и нехешируемые элементы без ключей используют
O(n*m) плюс стоимость рекурсивного сравнения. Строгая проверка дубликатов
для ключей только с равенством дополнительно может стоить O(n²+m²). Для больших последовательностей
структур задавайте хешируемый ID. Дополнительная память — O(n+m).
У совпадающего порядка ключей в FIFO-режиме индекс сопоставления не создаётся.
Ключи и элементы при сопоставлении не копируются. Обход переиспользует буферы
исходного и нового пути и копирует только возвращаемые значения/пути событий. Поиск в map стоит
O((n+m) log(n+m)), в unordered_map — ожидаемо O(n+m).

Прежние `diff()` и наблюдатели продолжают сравнивать последовательности по
индексам и не выдают `moved`. Числовые значения прежних видов событий сохранены.
Регистрация, компараторы, callbacks, настройки и история остаются доступны.
[Benchmark](performance.ru.md#benchmark-глубокого-сравнения) позволяет проверить
конкретные нагрузки; временных порогов в тестах нет.
