# API и семантика

Библиотека полностью находится в `include/vardiff/vardiff.hpp`.
Все примеры требуют C++20. Объект и наблюдатель должны оставаться живыми во время
вызова методов и callbacks.

## Описания полей и типы

field(name, member) использует `operator==`; для зарегистрированных структур
и стандартных контейнеров используется рекурсивное сравнение.
field(name, member, compare) использует переданный предикат равенства.
Предикат должен быть копируемым, вызываться как const и принимать два `const T&`.
Возвращаемое true означает равенство.

Поддерживаются копируемые типы с `operator==`, зарегистрированные структуры,
`std::vector<T>`, `std::optional<T>`, `std::array<T, N>` и их комбинации.
Поддерживаются также типы с явно удалённым move-конструктором, если копирование
разрешено. Тип с пользовательским компаратором может не иметь `operator==`.

Компараторы должны быть чистыми и давать стабильный результат для одинаковых
аргументов: один вызов API может сравнивать поле несколько раз.
Пользовательский компаратор делает поле атомарным: diff возвращает один элемент
с полным значением поля, включая контейнер или структуру. Внутренние пути такого
поля не обходятся.

Нулевые указатели на члены отклоняются с `std::invalid_argument`.
Битовые поля не имеют указателей на члены и не поддерживаются. Статические,
volatile и некопируемые поля в список наблюдаемых не входят.

Имена копируются. Для однозначных путей используйте непустые имена без точек
и квадратных скобок; библиотека не экранирует эти символы.

## Регистрация

Специализация `schema<T>` объявляет статическую функцию fields(), возвращающую
непустой `std::tuple` описаний полей. Объявляйте специализацию до первого
использования типа в field(), track(), diff() или changed().
Сначала регистрируйте вложенные типы, затем содержащие их структуры.
Рекурсивный контейнер собственного типа (например, `vector<Node>` внутри Node)
допускается: проверка сравнимости откладывается до использования описаний.

Схема должна возвращать одинаковые описания полей при каждом вызове.
Метаданные вложенных типов кешируются при первом обращении.
У зарегистрированного типа сравниваются только зарегистрированные поля,
даже если у самого типа есть `operator==`.

track(object, fields...) принимает только lvalue и сохраняет начальный снимок.
track(object, options, fields...) принимает параметры наблюдения.
Для зарегистрированного объекта доступны track(object) и track(object, options).

Объект заимствуется по адресу. Контейнеры внутри объекта могут изменять ёмкость,
но сам наблюдаемый объект не должен уничтожаться или перемещаться до окончания
его использования наблюдателем. Указатели и разделяемые ресурсы внутри
пользовательских типов копируются по правилам этих типов.

Копии наблюдателя наблюдают тот же объект и имеют независимые историю, курсор,
настройки и callbacks. Неизменяемые сохранённые данные могут совместно
использоваться внутри библиотеки. Изменение исходного объекта их не меняет.

## Чтение и события

| Вызов | Результат | Меняет снимок | Вызывает callbacks |
| --- | --- | --- | --- |
| changed() const | bool | Нет | Нет |
| diff() const | `vector<change>` | Нет | Нет |
| poll() | `vector<change>` | Если найдены изменения и включено автообновление | Если найдены изменения |
| snapshot() | void | Да, добавляет снимок | Нет |
| undo(), rollback() | bool | Перемещает курсор назад и восстанавливает объект | Нет |
| redo() | bool | Перемещает курсор вперёд и восстанавливает объект | Нет |
| rollback(position) | bool | Переходит к указанному снимку и восстанавливает объект | Нет |

Проверки происходят в момент вызова метода. Промежуточные изменения с возвратом
к исходному значению не обнаруживаются.

Порядок diff: порядок описаний полей; внутри структуры — порядок регистрации;
внутри контейнера — возрастающие индексы. Поле change.name содержит полный путь.
before и after — собственные копии в `vardiff::value`.
Изменения можно хранить независимо от объекта и наблюдателя.

`value.get<T>()` возвращает `const T&` и выбрасывает `std::bad_variant_access`,
если тип не совпадает или значение отсутствует. value.has_value() различает
отсутствующий элемент и имеющийся элемент со значением по умолчанию.
value.type() возвращает `std::type_info` сохранённого типа.

`operator<<` использует оператор вывода пользовательского типа, если он есть.
Иначе контейнеры выводятся как [a, b], зарегистрированные структуры как
{field: value}, пустой optional как `<missing>`, прочие типы как `<value>`.
Формат зависит от настроек потока. `operator==` для value сравнивает сохранённые
типы и значения; для типа, сравнимого только через компаратор конкретного field(),
он выбрасывает `std::logic_error`, поскольку этот компаратор в value не хранится.

## Контракт poll()

1. Выполняется проверка относительно текущего снимка. Без отличий возвращается
   пустой вектор, значения не копируются, callbacks и история не затрагиваются.
2. При наличии отличий копируются выбранные поля в проверенное состояние.
   Из него формируется неизменяемый список событий.
3. Callbacks вызываются в порядке регистрации. Callback всего наблюдателя
   получает `const vector<change>&` один раз. Callback пути получает
   `const change&` для каждого совпавшего изменения в порядке diff.
4. При включённом автообновлении проверенное состояние добавляется в историю.
   Возвращается тот же список изменений.

on_change(callback) подписывает на весь список.
on_change("items", callback) подписывает на изменения items и его потомков.
Префикс учитывает границы: подписка на hp не захватывает hp_max, подписка
на items[1] не захватывает items[10]. Пустые callback и путь отклоняются.

Изменение переменной само по себе не вызывает callback. Вызовы changed() и diff()
также не вызывают его.

Если callback изменяет объект, эти изменения останутся видимыми для следующего
poll(): снимок фиксирует состояние до вызова callbacks.
Регистрации callbacks, ignore() и set_auto_snapshot() внутри callback влияют
на последующие проверки. Список текущих событий и режим обновления уже выбраны.

Допустимы чтение changed(), diff(), history(), регистрация новых callbacks
и изменение настроек ignore/auto_snapshot внутри callback.
Рекурсивный poll(), snapshot(), undo(), redo(), rollback(), изменение лимита,
копирование, перемещение и присваивание активного наблюдателя отклоняются
с `std::logic_error`.

Если callback выбросил исключение, последующие callbacks не вызываются,
снимок и история не обновляются. Исключение передаётся вызывающему коду.
Изменения объекта и внешние эффекты уже выполненных callbacks сохраняются;
следующий poll() может сообщить об этих изменениях повторно.
Не храните переданную callback ссылку на вектор: при необходимости скопируйте его.

## Настройки и исключение полей

watch_options имеет значения по умолчанию:
auto_snapshot = true, history_limit = 64.

set_auto_snapshot(bool) меняет режим; auto_snapshot_enabled() возвращает его.
При отключённом режиме poll() сравнивает с прежним снимком до snapshot().
Тихий poll() не обновляет снимок даже при включённом режиме. Это также
предотвращает постепенное смещение базы при сравнении с допуском.

ignore(path) исключает путь и его потомков из changed(), diff(), poll()
и восстановления. Неизвестные пути допускаются: они могут появиться при росте
контейнера. Повторный ignore() не добавляет дубликат; пустой путь отклоняется.
Снимки по-прежнему содержат копии всех выбранных полей.

При восстановлении контейнеру возвращаются размер и наличие элементов
из снимка. Игнорируемые значения сохраняются, когда существуют и в текущем,
и в восстанавливаемом состоянии. Если элемент удаляется или создаётся целиком,
его структура берётся из снимка. Это относится также к наличию optional.
Например, ignore("items[2].price") не запрещает восстановлению удалить items[2].

## Контейнеры

vector и array сравниваются по индексу, без поиска идентичности или перемещения
элементов. Вставка в середину vector может изменить следующие индексы.

Общие элементы обходятся рекурсивно. Добавление и удаление выдаёт одно событие
с полным значением элемента. kind принимает modified, added или removed.
Для array размер фиксирован; для vector допускается изменение размера.
Поддерживаются `vector<bool>`, нулевой размер array и элементы без конструктора
по умолчанию.

optional с двумя значениями сравнивает содержимое по тому же пути.
Переход пусто/значение выдаёт added/removed с содержимым optional.
При добавлении элемента `vector<optional<T>>` само место в vector уже существует:
after.has_value() будет true, а `after.get<std::optional<T>>()` может быть пустым.

## История и восстановление

history() возвращает `vector<watcher::snapshot_type>`.
snapshot_type — tuple значений в порядке исходных описаний полей.
Это независимые копии: изменение результата не изменяет историю наблюдателя.
Для просмотра размера без копирования используйте history_size().

history_position() — индекс текущего снимка в возвращаемом списке.
can_undo() и can_redo() проверяют наличие предыдущего/следующего снимка.
Начальный снимок имеет индекс 0.

Явный snapshot() всегда добавляет запись, даже если значения совпадают.
Автоматическая запись появляется только после poll() с событиями.
При новой записи из середины истории будущие записи удаляются.
Без новой записи redo остаётся доступен.

undo() восстанавливает предыдущий сохранённый снимок, redo() — следующий.
Возвращают false без изменения объекта на границе истории.
rollback() равен undo(). rollback(position) восстанавливает выбранную запись,
включая текущую; последним вариантом можно отбросить несохранённые изменения
без перехода к другому снимку. Некорректный индекс вызывает `std::out_of_range`.
Ни один из этих методов не сохраняет несохранённые изменения автоматически.

При восстановлении меняются только выбранные поля, а у зарегистрированной
структуры — только её зарегистрированные поля. Ненаблюдаемые поля сохраняются.
Атомарное поле с пользовательским компаратором восстанавливается целиком.

Undo/redo/rollback доступны только для изменяемого объекта с присваиваемыми
выбранными полями. Восстанавливаемые вложенные листья также должны допускать
присваивание. Наблюдение const-полей и const-объектов, callbacks и история
не требуют возможности восстановления.

history_limit() возвращает лимит. set_history_limit(N) меняет его; N >= 1.
Лимит включает текущий снимок. При обычной записи удаляются самые старые записи.
Если лимит уменьшен после undo(), сначала удаляются старейшие записи до текущей,
затем самые дальние записи redo, пока размер не уложится в лимит.
Текущий снимок всегда остаётся; индексы history() после удаления меняются.

Захват снимка и добавление истории сначала подготавливают новое состояние.
Ошибка копирования/выделения памяти оставляет прежнюю базу и историю.
Восстановление вызывает присваивания пользовательских типов: если такое
присваивание выбросило исключение, объект может оказаться частично изменённым,
а курсор истории остаётся прежним.

## Вещественные числа и область применения

По умолчанию сравнение точное, через `operator==`. +0 и -0 равны;
NaN не равен самому себе и остаётся изменённым после snapshot().
Для другой семантики задайте компаратор, например учитывающий NaN или допуск.

Циклические графы указателей автоматически не обходятся. Обычные указатели
сравниваются как значения указателей, без обхода адресуемых объектов.
Многопоточность, JSON и автоматическая рефлексия не реализованы.
